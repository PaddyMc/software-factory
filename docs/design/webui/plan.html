Planned test additions: each verification command names its tests, so a missing test fails the gate rather than passing with zero selected.

Risks

  1. A case the starting tree already solves proves nothing. Action: bench-t01 checks that every shipped case fails its hidden tests before the reference solution is applied.
  2. Runs cost money. Action: --max-cost caps the whole run, and --dry-run prints the cells without starting one.

Problem

There is no controlled way to tell whether a change to a role prompt, a model or a flow made runs better. factory stats reports what happened on the board, but no two tasks are the same, so it can't compare two setups on the same work.

Design

factory bench run --flow default --flow strict --cases slugify,money-rounding --repeat 2
        │
        ▼  one cell per variant × case × repeat, each in its own FACTORY_HOME
   materialize case ─► factory run TASK --no-pr ─► gates ─► hidden tests ─► result.json

A case

  • A directory under factory/bench/fixtures/ with:
    • case.yaml: the contract, as in a plan;
    • repo/: the starting tree, committed as the base;
    • hidden/ and solution/, which the builder never sees.
  • A case is solved when its gates pass and its hidden tests pass on the candidate.
