## webui-t07: the run form and starting runs from the page

- Added `GET /run` for plan and task targets. The form mirrors the run mockup: dependency-ordered What will run rows and start/wait/running explanations, cost and attempt limits, plan-only parallelism, configured flows, an exact live-preview-compatible command, the cost warning, cancellation links, and per-request provider-key checks that disable Start run and name missing environment variables. Empty or refused targets explain why without rendering a form.
- Added token/origin-protected `POST /actions/run`. It shares scheduler/manual-gate target classification with GET, returns 409 for unknown or non-runnable targets, re-renders invalid fields with preserved values and errors at 400, and otherwise starts a detached `factory run` job with the shared preview flags. Plan runs include `--parallel`; task runs include `--quiet`; non-default flows include `--flow`. Run jobs redirect immediately to Activity with `Started the PLAN plan.` or `Started TASK.` notices.
- Added Run again links for failed, conflict, CI-failing and changes-requested tasks on the board and task pages, and Run plan links on cards with a currently `scheduler.startable` task. The cost cap defaults to the newest page-started run's cap, else `5.00`. Job records now carry an optional notice while remaining compatible with old records and positional callers.
- Added the six contract tests, including command argv, validation boundaries, missing keys, refusal/security cases and button placement, and updated the two earlier assertions affected by the new buttons. `app.js` already implemented the required preview order and was left unchanged; the only CSS addition is the field-error rule.
