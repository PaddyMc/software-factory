## webui-t01: WAL boards and skippable live updates

- `DB` now accepts a busy timeout (30 seconds by default) and sets WAL journal mode plus NORMAL
  synchronous mode on every open. A journal-mode switch that cannot get its lock is left for the next
  open without preventing the current open.
- Heartbeats and progress updates return whether they committed. A `database is locked` error rolls
  back the advisory write and returns `False`; other errors and all other writes still raise.
- `Pipeline._event` and `Pipeline._progress` log the required board-busy message when an advisory write
  is skipped, then continue the run. Cost-limit checks still run after a skipped progress update.
- Added coverage for WAL settings and persistence, rollback-journal conversion (including a locked
  conversion), eight concurrent writers with a `factory top`-style reader and an opener, and locked
  heartbeat/progress behavior through the pipeline.
