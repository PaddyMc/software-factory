# land-t02 — dry-run landing readiness (2026-11-27)

## What changed

- Added `factory/land.py:readiness`, which classifies a PR as ready, waiting on the factory, or waiting for a human using its board row, contract and GitHub state. The ordered reasons cover stacked bases, unexpected bases or heads, mergeability, pending/failing/missing CI, high-risk contracts and steering-file changes.
- Added `ci.pending` for incomplete check runs and pending/expected commit statuses.
- Added `factory land --dry-run`, repeatable `--plan` selection and `--no-sandbox`. The dry run uses a read-only board connection, reports open PRs in plan order, and performs no refresh, comment, merge or model call. Missing `land:` configuration and unknown plans are refused with the required messages.
- Extended the existing PR view with base and changed-file data while retaining the commit-based head fallback for older `gh` versions, and mapped the new command in the operator-interface specification.
